# C3 Scaffold Script Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the `code` stage. The Development Agent returns a file manifest, code renders it into one bash script, `bash -n` and shellcheck validate it, a repair loop fixes the files that fail, and the user downloads the script.

**Architecture:** The new package `app/modules/agents/code/` mirrors `agents/budget/`:
- `schema.py`: models
- `validate.py`: manifest rules, `apply_changes`, `plan_md`
- `render.py`: a pure renderer
- `check.py`: subprocess validators
- `prompts.py`, `agent.py`, `chat.py`, `mock_fixture.py`

Wiring follows the C2 pattern (stages, policy, registry, graph, conversations, artifacts router). The frontend adds `/projects/[id]/code`.

**Tech Stack:** FastAPI, pymongo async, LangGraph, `shellcheck-py`; Next.js 16, React Query, zod, SCSS modules, Vitest, Playwright.

**Spec:** `poc-backend/docs/specs/2026-10-28-c3-scaffold-design.md`

## Global Constraints

- No git commits; the user commits. No commit steps.
- Frontend styling uses SCSS modules only; never Tailwind.
- The platform never executes generated code. Subprocesses: `create_subprocess_exec`, stdin input, a 20 s timeout, `env={}` plus a `PATH` that contains the shellcheck binary.
- Artifact kind = stage = `"code"`, agent name `"developer"`, `LABEL["code"] = "Scaffold"`, and the agent label is "Development Agent".
- Limits: 1–60 files, path ≤ 200 characters, content ≤ 20 000 characters per file and ≤ 300 000 in total, ≤ 10 next steps of ≤ 200 characters, ≤ 30 changes, 2 repair rounds, `max_output_tokens` 14000.
- shellcheck runs with `-f json1 -S warning`. Both error and warning findings block approval. A missing validator gives `VALIDATOR_UNAVAILABLE` and blocks approval.

## Review Focus

1. Content that contains a line equal to `AMPERA_EOF` must round-trip. Test: `test_delimiter_collision_roundtrip` (Task 2).
2. Content with CRLF line endings or no trailing newline is normalised once at save, so the downloaded script writes exactly the stored content. Test: `test_normalise_crlf_and_newline` (Task 1).
3. A shellcheck finding in the renderer's own lines is our bug and must not go to repair. Test: `test_renderer_output_is_shellcheck_clean` (Task 2).
4. A chat change that deletes a missing path, or writes `PLAN.md`, is rejected with a clear message. Tests are in Task 1.
5. A rate change must not mark the scaffold stale. Test: `test_rates_change_keeps_code_fresh` (Task 4).
