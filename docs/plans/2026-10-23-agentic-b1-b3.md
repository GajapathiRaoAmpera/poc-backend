# Agent Runtime, Requirements Analyst, Architecture Studio (B1–B3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A governed agentic workflow: orchestrator + durable worker run a Requirements Analyst and Solution Architect via a provider-independent LLM gateway, producing immutable, validated, approvable artifact revisions, edited in an interactive Architecture Studio with AI change sets.

**Architecture:** New backend modules `llm/`, `artifacts/`, `orchestration/`, `agents/`, `diagrams/` in the FastAPI modular monolith on MongoDB; a separate worker process consumes a Mongo job queue. Frontend adds live pipeline, activity drawer, Requirements page and a React Flow Architecture Studio.

**Tech Stack:** FastAPI, PyMongo async, Pydantic v2, httpx (Groq), pytest · Next.js 16, TanStack Query, `@xyflow/react` 12, `elkjs` 0.12, Vitest, Playwright + axe.

**Spec:** `poc-backend/docs/specs/2026-10-23-agentic-b1-b3-design.md`

## Global Constraints

- Branch `feat/agentic` in both repos. Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Every new project route resolves the project via `get_project_for` (others → 404); every query on runs/events/artifacts/revisions/change sets filters by `project_id`.
- Revisions are never updated after insert (no `update_*` call on `artifact_revisions` anywhere in `app/`).
- Run statuses: `QUEUED, RUNNING, SUCCEEDED, FAILED, CANCELLED`. Stage statuses exactly as spec §4.3 table. Stages: `requirements`, `architecture` (+ reserved `plan`, `budget`, `code` reported as `UNAVAILABLE`).
- Job: lease 60 s, heartbeat 20 s, `max_attempts` 3, backoff `2^attempt·5 s ±20%`, `timeout_s` 180 (`AGENT_TIMEOUT_S`).
- Agent output repair: max 2 repair prompts, then `FAILED` with `error.code = "OUTPUT_INVALID"`.
- Quota: `user.daily_run_limit ?? PLATFORM_DAILY_RUN_LIMIT (50)` runs / rolling 24 h → `429 QUOTA_EXCEEDED`.
- New error codes: `STAGE_BLOCKED` 409, `REVISION_CONFLICT` 409, `NOT_APPROVABLE` 409, `QUOTA_EXCEEDED` 429.
- Requirement IDs `^(FR|NFR)-\d{3}$`; question IDs `^Q-\d{3}$`; node IDs `^n_[a-z0-9_]{1,40}$`; edge IDs `^e_[a-z0-9_]{1,40}$`; ADR IDs `^ADR-\d{3}$`.
- Diagram limits: ≤200 nodes, ≤400 edges, ≤30 groups, ≤50 decisions. Requirements limits: ≤150 requirements, ≤30 open questions.
- `LLM_PROVIDER=mock` refused when `ENVIRONMENT=production`; mock runs show "Mock provider" in the UI. `GROQ_API_KEY` never logged or returned.
- No test makes a network call to Groq.
- Brand tokens only (no new hard-coded colours); WCAG 2.2 AA; keyboard-operable studio.

## Review Focus

1. **Worker dies after writing the revision but before marking the run done** → on reclaim no second revision is created and the run ends `SUCCEEDED` pointing at the existing revision. (Task 4)
2. **User saves a manual studio edit while an AI change set is pending** → applying the change set returns 409 and marks it `SUPERSEDED`; manual edit intact. (Task 7)
3. **Approving requirements r2 while architecture r3 (built on r1) is approved** → architecture becomes `STALE` with a reason naming both revisions; approving architecture r3 again is refused until regenerated or re-saved. (Task 2/3)
4. **Model returns a diagram whose edge points to a node it forgot** → repair prompt lists the exact issue; after 2 failed repairs the run is `FAILED OUTPUT_INVALID` with a readable message, nothing persisted. (Task 5/7)
5. **SSE connection drops** (proxy idle timeout) → client resumes from last `seq` without duplicate or missing events, or falls back to polling. (Task 8/9)
